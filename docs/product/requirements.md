## 当前需求

### PRD-0001：Cursor 开发代理接入 V1

- **状态**：草案，待 ChatGPT 验收后进入开发。
- **业务目标**：让 EvoFlow 能安全地把带 EVO 编号的前端开发任务交给本机 Cursor Agent 执行，并将计划、批准、执行事件、验证结果与 PR 链接沉淀为可审计记录。
- **目标用户与场景**：项目负责人从 EvoPanel 创建 Cursor 任务；前端开发者在任务开始前检查计划和影响文件；审核者在合并前查看 diff、检查结果与分支/PR。
- **范围**：
  - 发现并预检已安装、已登录的本机 `cursor-agent` CLI；不替用户安装或保存 Cursor 凭据。
  - 以 EVO 任务为唯一入口，创建独立 Git worktree 与任务分支，默认只允许分析/规划。
  - 对写入代码、运行可能修改工作区的命令设置显式批准关卡；批准后仍只在隔离 worktree 中执行。
  - 在 Gateway 保存任务状态、经过脱敏的事件、退出结果、验证记录、diff 摘要和 PR 链接；EvoPanel 提供任务详情和批准界面。
  - 将 Cursor 的实现封装为可替换 Adapter，为后续 Codex Adapter 复用相同的任务协议。
- **不在范围内**：
  - 不把 Cursor 或 Codex 伪装成 EvoFlow 的模型供应商；模型调用仍按现有模型 Provider 边界处理。
  - 不自动安装 Cursor CLI、自动登录、托管 `CURSOR_API_KEY`，或把用户的凭据写入数据库和日志。
  - 不允许 Agent 在 `main`、`develop` 或用户正在工作的 checkout 直接修改文件；不自动合并、推送或发布。
  - 不在本期接入 Codex 客户端、云端队列、多人并发调度或远程执行主机。
- **依赖与约束**：
  - 用户本机须已安装并认证 Cursor CLI；Gateway 只调用受控的可执行文件与固定参数，不拼接用户输入为 shell 命令。
  - 必须先合并 EVO-0004 与 EVO-0005，确保开发入口和 AI 路由规则可用。
  - 每次执行从 `develop` 创建的任务分支与独立 worktree 开始；任何写入需要批准记录。
- **验收标准**：
  - [ ] 用户可从 EvoPanel 看到 Cursor CLI 的可用性、认证状态与不可用原因，且界面不显示密钥。
  - [ ] 用户可通过一个 EVO 编号创建只读规划任务；任务不会改动 Git 工作区。
  - [ ] 写入任务在批准前不能启动；批准后只能在该任务的隔离 worktree 和允许路径内改动。
  - [ ] 每个任务展示状态时间线、脱敏事件、分支、diff 摘要、检查结果和可选 PR 链接。
  - [ ] 任务失败、取消、CLI 不可用或验证失败均有可读错误状态，且不会影响 `main` 或 `develop`。
  - [ ] 为 Adapter、任务状态机、审批关卡和事件脱敏添加自动化测试。
